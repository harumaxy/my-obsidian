チャンネル: Shin Coding Tutorial (登録者 約13.6万)

## 動画の主旨

- 「ぬい日和」= ぬい活(ぬいぐるみ活動)専用SNS。6万ユーザー超。個人開発。
- 運用・開発・保守、全部 Claude Code。1人。
- 字幕の「縫い病理」は誤変換。正しくは「ぬい日和」。
- 前回動画の「秘書AIが各セッションに指示するオーケストレーション」はやめた。
  - 理由: 事業の方向性 (UI、オンボーディング、分析から舵取り) は AI 単独で決められない。
  - ゴール明確な作業 (テスト通るまで実装) なら、オーケストレーション・ループで完結する。
  - 事業規模になると、人間が意思決定する必要あり。

## 体制 (スライド)

- 中心にオーナー1人。周囲に用途別セッション8つ。
  - 経営戦略 / 獲得ハック / フィードバック対応(`/triage`) / Android / 多言語対応 / モデレーション / UI/UX改善 / パフォーマンス
- 右側に Skills ×3。下に CLAUDE.md と Memory。「ルール化」して書き戻す → 「育てる」循環。
- Claude Desktop 使用。セッションを会社の「部署」とみなす。各セッションに固有コンテキスト。
- アプリのディレクトリ全体 = 会社の脳。Claude は読めば進捗が全部分かる。
- セッション間メッセージ受け渡し (Desktop の新機能)。オーナーが指示した時だけ許可。
  - 例: フィードバックの要点を経営戦略セッションに渡す。

## 運用の中身

- 1日の意思決定 100〜200回。送信 → レビュー → 次の指示、を各セッションで回す。
- 同時並行は最大4セッション。3つが適正。人間のマルチタスクがボトルネック。
- 音声入力 (Typeless) で全部喋る。PC もスマホも。キーボード入力ほぼなし。精度への言及なし。
- 経営戦略セッション = 共同創業者役。
  - 材料: インストール数、DAU、ユーザーのフィードバック。
  - 例: 「新機能より穴を塞ぐ」。市場調査やバズ予測をやらせる話はなし。
- 特別なプロンプト・ハーネスは使わない。1回1回丁寧にやり取りする。

## トリアージスキル (`/triage`)

- フィードバック累計 約800件。毎日 5〜10件。全部は捌けないので優先順位付け。
- 流れ:
  1. 50件ずつ並列で読む
  2. 分類サブエージェント: バグ / 要望 / 質問 / 感想
  3. バグ → バグ調査係。要望・質問 → 要望判定係 (アプリのコンセプトとガイドラインに照らす)
  4. 並列で進行 → レポート1本にまとめる
  5. オーナーが「赤ペン」で採点
  6. 判断例をガイドライン MD に追記 → 次回の判定精度アップ
- ハーネス自体は Claude に「こういう問題を捌くもの作って」と頼んで作らせた。
- 高速な仕分け技術 (字幕では「ジェブ」。正式名不明) は不要と判断。普通に Claude Code で10〜20分待てばよい。
- 結論: ゴールとタスクが明確な作業にはハーネスが効く。

## レビュー徹底

- 全セッションの出力を自分で理解して次を返す。意思決定は外注しない。
  - 数万人が使う本番に反映されるから。
  - 自分で舵を引かないと、事業のコントロール感を失う。モチベ低下、事故の元。
- 成果の差 = 知識とセンスの差。AI は増幅器。
  - 例: スケルトンUIを知らず「読み込み中」文字だけにする。要素・ボタンの詰め込みすぎ。
  - 知識がないと気づけず、指示も出せない。言葉選び、絵文字などの細部もセンス。
- だから勉強する。優れた作品に触れてセンスを磨く。
- 上流工程 (意思決定) だけ人間に残る。それも将来 AI に置き換わるかも。

## 学びの蓄積

- 方針変更・デプロイ前チェック・セキュリティ確認 (他人IDで削除できないこと等) を CLAUDE.md とメモリに溜める。
- 同じミスを繰り返さない。人間の学習と同じ。
- 「自己改善ループ」「ループエンジニアリング」「グラフエンジニアリング」は名前が派手なだけ。やってることは大したことない。踊らされるな、という主張。

## 補足: 用語

- グラフエンジニアリング = 複数エージェント・ツール・検証を有向グラフで設計。順序、分岐、並列、受け渡しを構造で決める。
  - ループ = 自分に戻る辺を持つ最小のグラフ。
  - フローチャートに近い。違いは、図がそのまま実行定義になる点。
  - 利点: 状態保存と再開、人間の割り込み、可視化、リトライ宣言。単純なフローなら普通のコードで十分。
  - 主なFW: LangGraph / Microsoft Agent Framework / Google ADK / CrewAI / LlamaIndex Workflows / OpenAI Agents SDK
  - 注意: 単一エージェント精度が高いタスクでは逆効果。AIがAIを検証するだけだと「整然としたナンセンス」になる。外部の決定的な検証器が要る。
- 自己改善ループ = 結果や失敗を CLAUDE.md・メモリ・ガイドラインMDに書き戻す仕組み。

## 感想・注意点

- 新しい技術はなし。Claude Code 標準機能 (セッション、スキル、CLAUDE.md、メモリ) の組み合わせ。違いは規律: 役割で分割、判断は人間、学びを書き戻す。
- 本人の負荷は大きい。AI に任せる量が増えても、人間の判断コストは増える。
- 数値の根拠なし。全部自己申告。動画終盤に自分の講座 (ShinCode Academy) の宣伝あり。割り引いて聞く。
- 再現性の疑問: 登録者13万超のインフルエンサー。初期流入への影響は不明。
  - ぬい日和: iOS版 2026-06-17 リリース。7月下旬にバズって約4万人。バズの経緯は ITmedia 記事にも記載なし。
  - 再現性があるのは運用ノウハウ。ユーザー獲得の再現性は動画の対象外。
- 獲得ハック・モデレーション・多言語対応セッションの中身、Skills ×3 の名前は動画で語られていない。
