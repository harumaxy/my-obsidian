# なぜデプロイは怖くなくなったのか

- チャンネル: IT技術屋のボヤキ
- URL: https://www.youtube.com/watch?v=_I3N9fyi6vY

## CI以前：統合フェーズという地獄

- 1990年代、各チームが数ヶ月バラバラにコードを書いて最後に一気にマージする「統合フェーズ」が当たり前だった
- 「インテグレーション地獄」：6ヶ月開発して統合だけで3ヶ月かかるプロジェクトも存在
- 誰の変更が原因か分からずチーム同士が責任を押し付け合う
- Microsoft は早くからデイリービルドを導入（壊した人が翌日のビルド番人になる罰ゲーム付き）

## CIの誕生：逆転の発想

- **グレイディ・ブーチ**（1991年）が「継続的インテグレーション」という言葉を作る
- **ケント・ベック**（1996年）がXPの中で「1日に何度も統合する」規律を実践
  - 回数を増やしたら痛みが消える、という直感に反する発見
  - 統合の痛みは変更量が増えるほど爆発的に膨らむ → 小さく頻繁にやれば痛みはほぼ消える
- **マーチン・ファウラー**（2000年）が論文として体系化
- 2001年、世界初のCIサーバー **CruiseControl** がOSSで公開

## Jenkinsの誕生：日本人エンジニアの「恥をかきたくない」動機

- **川口耕介**（Sun Microsystems）が2004年、「コミットでビルドを壊して迷惑をかけたくない」という個人的な動機から **Hudson** を開発
- CruiseControlより設定が簡単でプラグイン拡張が自由 → 爆発的に普及
- 2010年Oracleが買収 → 商標問題でコミュニティと衝突
- 2011年、214対14の投票でコミュニティが独立 → **Jenkins** に改名
- OracleのHudsonは2020年に引退。名前を捨てた側が本体として生き残った

## CDの誕生：デプロイを日常業務に

- 2009年6月23日、Velocityカンファレンスでフリッカーが「**1日10回以上のデプロイ**」を発表
  - 当時は月1回でも先進的な時代。会場がざわついた
- 2010年、**チェズ・ハンブル**らの著書「継続的デリバリー」で体系化
- 2011年、**Travis CI** が登場（GitHubと連携するクラウドCI）
- 2018年、**GitHub Actions** により「コードのある場所にCI/CDが最初からついてくる」時代に

## CICDが本当に変えたもの

DORA Research（2018年「Accelerate」）の調査結果：

> **デプロイ頻度が高い組織ほど障害が少ない**

- エリート組織はデプロイ頻度が低パフォーマンス組織の数百倍、変更失敗率の回復も数分
- 「慎重にまとめてたまに出す方が安全」という旧来の常識は**逆だった**
- 変更が小さいほどリスクが小さく、頻繁にやるほど作業が上手くなる

最大の効果は**心理的変化**：

> デプロイが怖くなくなるとエンジニアが挑戦するようになる。
> 失敗してもすぐ戻せるから実験のコストが下がる。
> CDは開発の道具である前に、**組織の勇気を生む装置**だった。

## 現代のCI/CDツールシェア（2025-2026年）

JetBrains State of CI/CD 2025 調査より：

| ツール | 個人プロジェクト | 組織・企業 |
|---|---|---|
| **GitHub Actions** | **62%** | **41%** |
| Jenkins | - | 28% |
| GitLab CI | - | 19% |
| CircleCI | - | ~6% |

- Jenkins が28%も残っている理由：Fortune 500の80%がまだ依存。大企業ほど移行コストが巨大
- Travis CI・CircleCI は縮小傾向。Travis CIは2020年にOSS無料提供を廃止してから急速に衰退
- 32%の組織が複数ツールを併用（旧Jenkinsから移行中にGitHub Actionsを並走）
- **個人開発・スタートアップ・GitHubをSCMにしている組織なら「GitHub Actions一強」でOK**

## Jenkins と Travis CI のアイコン由来

### Jenkins：執事キャラクター

- 「Jenkins」は英語圏の執事（バトラー）の定番名
- P.G.ウッドハウスの小説の名執事「ジーヴス（Jeeves）」からインスピレーション
- コンセプトは「**開発者に仕える執事**」。ビルド・テストを自動でこなす召使いのイメージ
- 川口耕介さん本人も「バトラー（執事）」と表現。ロゴは2010年に作成

### Travis CI：口ひげのおじさん

- 名前「Travis」の公式な由来説明はなし。創業者（ベルリンのドイツ人チーム）が英語らしい人名として選んだ可能性が高い

### なぜ当時のツールは「おじさん」キャラが多いのか

- 2010年前後のDevOpsツール界隈では「信頼できる古参のベテラン・職人気質」というイメージが好まれた
- GitHub Actions にはマスコットがなくGitHubブランドに統合されているため、現代的に見える
