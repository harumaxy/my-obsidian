# サーバー構築が上手いことは、本当に強みなのか

- 動画: https://www.youtube.com/watch?v=4sBX00kwrMc
- チャンネル: IT技術屋のボヤキ (2026-09-25)

## 動画の主張

サーバー構築の価値、「作れる」から「中身を分かっている」へ移った。
借りるか持つか選ぶ力、障害の時どの層が漏れたか指せる力、これが強み。

### 1章: サーバー 20年で隠された

- 2006 EC2: 買う物から借りる物へ
- 2012 ペットと家畜: 名前付けず入れ替える
- 2014 Lambda: サーバーレス化
- サーバー消えたのではない。隠しただけ

### 2章: 隠したもの 漏れた日

- 2025/10/20 AWS us-east-1 障害。DynamoDB の DNS 異常から連鎖、復旧 14時間半
- 待つしかなかった会社と、別リージョンへ逃げた会社。差は依存関係を知っていたか
- Spolsky「漏れのある抽象化の法則」: 抽象化は必ず漏れる。漏れた時、下の層の知識が要る
- 抽象化はコストを消さない。支払いを後ろにずらすだけ

### 3章: クラウド見直し

- 2021 a16z「クラウドコスト 1兆ドルのパラドックス」
- CIO調査: 一部オンプレ回帰 43%(2020末) → 83%(2024)。全面撤退は 8%
- 37signals は 2023年にクラウド離脱、約200万ドル削減
- 選び直すには、マネージドと自前の両方を知る必要あり

### 4章: AI の影響

- 構築は AI エージェントに頼める時代。手を動かして覚える入口、消える
- 皮肉1: 構築の手間消えても障害は消えない。中身説明できる人が減る
- 皮肉2: AI エージェントは常駐先が要る。サーバーレスの先でサーバー、戻ってきた
- 結論: 構築の価値 = 借りている物の中身を説明できること

(途中、Hostinger VPS の広告。クーポン ENGINEER10。自分で触る練習台として推し)

## 考察 (会話で出た論点)

### マルチリージョンも抽象化では?

- その通り。Route 53 フェイルオーバー、Aurora Global、DynamoDB Global Tables は、中身知らなくても冗長化できる抽象化
- 障害で効いたの、Linux やポートの知識ではない。**依存の地図**
  - どのマネージドに依存しているか
  - リージョン落ちたら何が止まるか
  - コントロールプレーン障害時は新規リソースが作れない。待機環境を先に用意
- 構築経験は一つの手段にすぎない。設計レビュー、Game Day、Well-Architected でも同じ理解に届く
- 動画の「構築経験 → 依存理解」、少し飛躍がある

### 結局「別のマネージド知識を網羅しろ」に帰結する?

- 実務ではほぼそう。AWS 全体が落ちたら、低レベル知識で直せない。逃がす知識が要る
- ただし完全には帰結しない
  - マネージド足しても抽象化の層が増えるだけ。終わりがない
  - 自前の最小構成(VPS)は、最後の逃げ道として別の性質を持つ
  - 自前は運用負荷が高い。多くの会社でコスパ悪い
- 重要度で割り切る
  - 止まってもよい: シングルリージョン マネージド
  - 少し困る: マルチリージョン + 切替訓練
  - 止められない: マルチクラウド or 自前の逃げ道
- 低レベル知識は全員必須ではない。最終防衛線の担当者が持てばよい

### クラウドから自前へ戻す動きの読み方

- 「83% が一部回帰」は大企業CIO調査 + 「一部ワークロード」という広い定義。実態は巨大・安定・予測可能な負荷だけ
- 37signals は条件が揃っていた(負荷安定、人材あり、規模大、生存者バイアス)
- 全面撤退 8% の方が実態に近い
- クラウドの価値はサーバー代ではない。調達、保守、障害対応、スケール、立上げ速度の人手削減
- 自前が有利: 負荷安定、クラウド費が人件費を大きく超える規模、egress 巨大、人材に余力
- 余力ある人材を遊ばせるのはもったいない。ただし属人化・24時間責任のリスクあり
  - まず開発環境、バッチ、社内ツールなど非クリティカルから

### 人件費 vs サーバー代、Vercel 系

- 大多数の会社は人件費の方が重い。エンジニア1人 約1000万円/年
- Vercel 系の価値 = 開発者の時間を買う(プレビュー環境、ロールバック、CDN、自動スケール)
- 落とし穴
  - 従量課金が跳ねる(帯域、関数実行、画像最適化)
  - ロックイン(Next.js 機能依存)
  - 大規模で損益逆転。Cloudflare や自前の方が安くなる
- 小〜中規模: マネージドが総コスト最安。インフラ人材不要
- 動画の「自前で構築しろ」 = 規模の上端にいる会社の話。普通の開発者は、依存関係とコスト目安を知っていれば十分

## まとめ

- 構築スキル自体が強みではない。**抽象化の下で何が起きるか推測できる力**が強み
- 判断は知識より、コスト試算と運用体制で決まる
- 動画は広告枠を挟むので、「自分で触れ」は少し誘導的
