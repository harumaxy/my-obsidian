## 前提

- 仕事後コード書く気しない → 脳エネルギー切れ。意志力 問題 ちがう
  - ハードル極小化、朝30分、前日続きメモ、休む許可
- 自分でサービス作って稼ぐ人、いる。ただし少数
  - 個人開発手出す人 エンジニア 2〜3割
  - 月数万円以上 稼ぐ 5〜10%
  - 生活できる額 (月30万〜) 1%前後
  - 大半 ゼロ円 or サーバー代トントン。収益 べき乗分布
  - 現実的ライン = 副業で月数万〜十数万

## 技術力 と 売る力

- 技術力 = **必要条件**。最低ライン 超えたら あと 効かない
- 1人で 設計 実装 インフラ 運用 全部 やる = 深さ より 広さ
- Rails, PHP, jQuery でも 稼ぐ人 いる。凝る = 出荷遅れ = 負け筋
- 技術強いのに 稼げない人 大量。作って満足 パターン
- 差つくの = 課題選び、集客、継続
- 技術力 低い ではない。**限界効用 低い**

## 売れるサービス の 作り方

独創性 いらない。パクって安売り 以外 にも 道ある。

- 自分の 仕事 / 業界 の 痛み
  - 非エンジニア業界 (不動産 医療事務 飲食 士業) IT化 遅れてる、既存ツール 使いにくい
- 既存サービス 不満 拾う
  - 競合レビュー、X、Reddit の「ここ 不便」
  - パクリ ちがう。**特定層向け 特化版**
- 安売り でなく **絞る**
  - 汎用ツール → 「歯科医院向け 予約」。ニッチ = 大手 来ない
- 無料ツール あっても 売れる
  - 無料 = 面倒 (設定 保守 統合)。**手間の代行** に 金払う
- 日本ローカライズ
  - 海外 SaaS の 日本商習慣対応 (請求書 インボイス LINE連携)

金払う条件:

- 時間 or 金 節約 / 売上増 に 直結
- B2B > B2C。会社 経費 で払う、価格 敏感ない
- 痛み 強い (なくて困る) > あると便利

## 需要 調べる 場所 (ネット中心で OK)

引きこもり ネット民 = 弱点ちがう。需要 ネット上 可視化済み。

- Reddit / X / 5ch / 知恵袋 / note
  - 「〜 面倒」「〜 ない？」「誰か作って」検索。生の不満
- Product Hunt / Indie Hackers
  - 売れてる 個人開発 + 収益公開
- App Store / Chrome Web Store
  - ランキング + レビュー。★2〜3 の不満 = 改善余地
- G2 / ITreview
  - 低評価コメント = 差別化ポイント
- Google Trends / キーワードプランナー / Ahrefs 無料版
  - 「〜 ツール」「〜 テンプレ」検索ボリューム
- Gumroad / BOOTH / note 有料記事
  - 実際 金払ってる ジャンル
- ココナラ / クラウドワークス
  - 「〜 やって」依頼 = 自動化 需要。作業 → ツール化
- GitHub Issues
  - 人気 OSS の 欲しい機能

## アンテナ 鍛える

- 毎日10分 **不満ログ**。愚痴 面倒 メモ。1ヶ月で パターン見える
- 自分の 不便 記録。一番近い ユーザー = 自分。「毎回 手作業」= 候補
- 売れてるもの 分析。「なぜ 金払う？」毎回 言語化
- 競合 実際 買う / 使う。課金体験 LP オンボーディング 観察
- 他人の 個人開発 追う。X の 収益公開 人。売れ方の型 学ぶ

## 検証 (作る前)

- LP 作る → 待機リスト / 事前決済
- X 発信 → 反応見る
- 「金払う？」直接聞く。**「欲しい」と「払う」は別**

進め方:

1. 不満ログ 溜める
2. 課題 候補 絞る
3. LP + 事前申込 / 手動代行 で 需要確認
4. 最小版 作る。金払う人 1人 目標
5. 払う人 の 要望 聞いて 育てる
