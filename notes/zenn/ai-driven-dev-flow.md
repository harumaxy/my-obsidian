## フロー全体

`リファインメント → プランニング → 実装 → 多層AIレビュー → 自動化CI → 人間レビュー`

## リファインメント

スクラム用語。スプリント前にバックログアイテムを具体化・見積もる会議。\
ここでは `grill-us` スキル（Claude Code カスタムスキル）でAIファシリテーション。

**grill-us が自動化する内容:**
- Jira チケット取得・目的/背景/現状 要約
- コードベース自動調査（画面/GraphQL/権限/feature flag/既存テスト/類似実装）
- 残った不明点をインパクト順整理 → チームに質問
- 合意内容をチケットに反映（共通認識・仕様・受入条件・QA観点・未決事項）

「コードが答えられること = AI調査、チームは判断のみ」設計。2〜3人で認識統一。

## プランニング

スクラム用語。次スプリントで何をやるか決める会議。\
仕様が詳細に詰まってるので「順番とキャパシティ」調整のみに簡略化。

## 実装 + 多層AIレビュー

- **Claude Code** → 仕様をプロンプトとして実装
- **Copilot** → `.instructions.md` 基準の規範チェック（命名/フォーマット/社内ルール、ルールベース）
- **Codex(GPT)** → 探索的レビュー、構造バグ発見
- **厚いCI** → テスト/リンター/ビジュアル回帰テストで機械的保証

異なるモデルで役割分担 → 得意/苦手パターンが違う → 死角減少。

## babysit-pr

CI失敗・レビュー指摘を自動修正ループ。全クリアしてから人間にPR届く。\
→ 人間には検証済み高品質PRのみ。

※ローカルでCI同等テストを回せるならそちらの方が速い。CI待ちが現実的なのは環境依存テスト・ビジュアル回帰・大規模モノレポ等のケース。

## 感想・疑問点

**多層AIレビューの効果について:**\
Claudeのみ別セッションでも第三者視点は保たれる（コンテキスト無しのため）。\
「モデル多様性」の本質はセッション独立ではなく「Claudeが苦手なクラスのバグをGPTが拾う」かどうか。\
定量的根拠は記事内になく、効果は不明。

**肝:**\
リファインメントフェーズでAIに事前調査させ不確実性を削ぐ設計。\
実装もレビューも複数AI役割分担。\
babysit-prでS/N比上げてから人間に渡す。
